# しらすの山

一人称3D × 物流・工場自動化 × ちりめんモンスター収集。企画書 v2.0 をもとにしたブラウザゲームです（Three.js / Vite / GitHub Pages）。

1,000万匹のしらすの山から、しらすをつまんで計量機に運び、パックにして売る。手に入れたお金で手袋やスコップを買い、山を削っていくと、最初から埋まっていた「ちりモン」が見つかる。見つけたら保護ケースへ。うっかり計量機に入れたまま包装すると「見逃し（誤出荷）」になる。

## 実装範囲（企画書 7章の P0〜P6）

- **P0 技術検証**：一人称移動、つまむ／はなす、計量機、包装・出荷。個体は手・床・計量機・出荷済み・保護ケースのどこか1か所にだけ存在し、複製されない（記録画面の「整合性を検査」で確認できる）。
- **P1 山の実体**：1,000万匹すべてに固有ID。ワールドシードとチャンク（10cm角の柱）から位置・回転・形状を決定論的に再生成。除去状態は 1.25MB のビットセット。近景＝実モデル（InstancedMesh）、中景＝簡略メッシュ、遠景＝除去状態を反映した表面メッシュ。
- **P2 収集**：7種類のちりモンを生成時に配置（後から湧かない）。山を削ると露出、保護ケースで図鑑登録、計量機経由で出荷すると見逃し。恒久図鑑。
- **P3 物流**：手袋4段階（素手2→4→8→20→50匹）、スコップ／大スコップ、運搬箱・台車（スコップで何度もすくってためる）。建設画面（一時停止中の上面図・0.5m グリッド）で **コンベア・ホッパー・包装機・クレーン** を設置。クレーンは可動範囲で一番高い所から実在IDを取り除き、ホッパー → コンベア → 包装機（または計量機）へ流れて出荷される。機械はちりモンを見分けないので、混ざったまま包装されると見逃し。設備は E で停止でき、ベルト・ホッパーから手で取り出せる（ちりモン優先）。
- ちりモンの配置：開始時に露出しているのは1〜2匹だけ。大半は表面から 1.4cm より深くに埋まっている（旧版のセーブは旧配置のまま）。
- そのほか：長靴・自動包装・ルーペ、画質プリセット（低／標準／高・動的解像度）、スマホ操作、設定（感度・FOV・揺れ・照準補助・文字サイズ・左手配置）、IndexedDB自動セーブ、チュートリアル。

- **P4 工場設計**：
  - 占有マス・向き・入口／出口：包装機は1×2マス（後ろの面から受け取り、正面の出荷口マスを空ける）、発電機は2×2マス＋周囲1マスの通路。コンベアは正面から受け取らず、包装機・選別機は後ろの面からだけ受け取る。
  - 人の通路：置くと計量機・棚・保護ケース・端末・受電盤・山の裾へ歩いて行けなくなる設備は置けない（グリッド上の到達判定）。
  - 電力：受電盤（3kW・無料）、発電機（12kW・負荷1kWあたり1.2円/秒の燃料費。0.8.0〜）、電柱（電線で5m先とつながり半径3mに配電）。配電範囲外の設備は動かない。不足すると優先度（高・中・低）の低い設備から停止、足りなくなった優先度の設備はそろって減速（0.7.0〜）。
  - 選別機：ライン途中で、ちりモンを検出率85%（個体ごとに決定論的）で回収箱へ分ける。回収箱がいっぱいだと止まる。
  - 建設画面に配電範囲・電線・優先度・問題のある設備（!）を表示。HUD に電力の需要／供給。
  - P3 までのセーブ：設備がある場合は発電機1台分の費用を一度だけ支給。1マスだった包装機は、2マス目がふさがっていれば撤去して全額返金。

- **P5 マルチ端末**：
  - セーブ：IndexedDB の2つの枠に交互に保存し、読み込み時に個体の保存則で検証。壊れていれば一つ前から復元。セーブ形式の版を移行（v1→v2）し、新しすぎる版は上書きしない。永続ストレージを要求。15秒ごと・アプリ切り替え時（自動で一時停止）に保存、手動セーブあり。
  - 書き出し／読み込み：gzip＋ビットセットのRLEで数KBのファイルにし、PC ⇄ スマホでセーブを移せる（スマホは共有シート）。
  - スマホ操作：照準補助「自動」（スマホは強）、ボタンの大きさ、「はなすを長押しで実行」（誤タップ防止）、振動、全画面・横向き固定（対応端末）、建設画面のピンチ拡大。
  - 画質：解像度・近景の密度・影・描画距離・FPS表示を個別に上書き。自動画質は GPU 名も見て選び、重い状態が続くと一段下げる。描画コンテキストが失われたら保存して再読み込みを案内。

- **P6 公開**：
  - 目標の矢印：今向かう場所（山・計量機・端末・保護ケース）に3Dの目印、画面外なら画面の端に矢印。まだ一度も保護していない人には、近くで露出した最初のちりモンだけ教える（設定で OFF 可）。
  - ちりモン配置 v3：開始時の「まぐれ」露出は山の裏側へ。計量機側の斜面の 1.5〜3cm に、よくある種類を数匹。初めての人をまねた自動プレイで、**最初の出荷は数分、最初のちりモン回収は約10〜25分（全シードで回収できる）** を確認するテストを追加。
  - 短期クリア：1山を処理し尽くすと成績画面（処理時間・出荷・発見・見逃し）。
  - エラー時に進行状況を保存して案内。バージョン表示・更新履歴。ホーム画面に追加（Web App Manifest・アイコン）、共有時のプレビュー画像。
  - ブラウザ通しテスト（`npm run e2e`）：PC とスマホで「出荷 → 手袋購入 → ちりモン保護 → 再読み込みで復元」。

- **0.7.0 プレイテスト後の改善**：
  - セーブ：復元処理が元データを書き換えて個体が重複する不具合を修正。検証に通らないセーブは別の場所に退避したうえで自動修復（所在不明の個体は出荷済みとして数え直す）し、その旨を表示。
  - 掘る手応え：掘った場所ほど山の表面の色が濃くなる。照準の下に「ここは ○cm 掘った」と、浅く埋まったちりモンの「気配」（かすか／強い／すぐ下）。目標 5/5 では、初めての出会いが埋まっている計量機側の斜面を矢印で示す。
  - ちりモンの「何かいる」表示が出ていれば、周りのしらすより優先してつまむ（表示と判定を一致）。手がいっぱいのときは案内を表示し、同じトーストは連発しない。
  - 包装：計量機にちりモンがいると自動包装は止まり、手での包装は1回目は警告（もう一度で包装）。山を処理し尽くしたら最後の端数（20匹未満）もパックにでき、短期クリアに必ず届く。
  - 搬送・電力：コンベアは計量機の東西南北どの面からでも搬入できる。電力不足では同じ優先度の設備がそろって減速し、搬送（コンベア・ホッパー）は既定で優先度「高」。設備の間の1マスの通路を実際に通れるように当たり判定を調整。撤去した設備の GPU 資源を解放。
  - スマホの建設画面：指を離したときに設置を確定し、ピンチ中は置かない。
  - 素手で2匹・手袋で4匹つまめる（序盤の往復を半分に）。道具の並び・「次の道具」の提案を費用対効果の順に。完成パック棚にパックが並ぶ。

- **0.8.0 経済の調整（手作業の天井と自動化の価値）**：
  - 手作業：スコップ 100匹（3,000円）、運搬箱 300匹（2,500円）、台車 500匹（6,000円）、大スコップ 200匹/すくい（4,000円）。50匹を超えて持つと足が遅くなり、600匹で半分の速さ（HUD に「重い：足 -○%」）。手作業の上限はおよそ 50〜60円/秒。
  - 自動化：クレーンは 360匹を 3秒周期でつかみ、包装機は 0.15秒ごとに包装。クレーン1台のラインで約 100円/秒（燃料費 約9円/秒を引いて約 90円/秒）。クレーンは低い柱もつかみ、山を最後まで片付けられる。燃料費は 1円単位で支払い、所持金は整数のまま。
  - 目安：全道具 約35分 → 最初のライン 約45分 → 以後はラインの増設で山（1,000万匹）の処理を早める。
  - あわせて：保存の瞬間に状態を複製（保存中の操作でセーブの個体数が合わなくなる不具合を修正）。「気配」は 2.2cm 以内のちりモンに反応し、方向（右・左・奥・手前）を表示、真上まで掘ると「すぐ下に何かいる！」。「ここは ○cm 掘った」は周りの柱も含めた値。「次の道具」は スコップ→運搬箱→台車→大スコップ の順。設備の間の1マス通路を広めに。

- **0.9.0 拡張期の経済**：
  - クレーンと発電機は台数ごとに値段が上がる（クレーン 15,000 → 25,500 → 43,300 …、発電機 ×1.5）。4本目のラインで元が取れるまで約15分、それ以降はさらに長くなる。クレーンの撤去は全額戻る（移設しやすく）。建設画面でクレーンを置く前に「届く範囲に 約○万匹」を表示。
  - 工場の改良（購入端末。クレーンを1台置くと買える）：長いアーム（腕 3.2m）25,000円、高速包装機（0.09秒）40,000円、高速クレーン（1周期 2.2秒）60,000円、大きなつかみ（540匹）150,000円。ホッパーの送り出しを 0.25秒間隔に。
  - 燃料費は後払いできる（所持金が0でも発電機は動き、売上から払う）。届く範囲が空のクレーンは待機（0.3kW）になり「届く範囲にしらすがない」と表示。包装機が詰まると「包装が追いつかない」。
  - 序盤の短縮：作業グローブ 800円、スコップ 2,000円。大スコップ（2,500円）は運搬箱の前に。重さの表示は5%以上の減速から、台車（500匹）で最も遅く（-45%）。「すぐ下に何かいる！」は5cm以内。

- **0.10.0 山の崩れ**：
  - 隣の柱より 0.11m（1マス0.1mあたり、安息角 約48°）以上高い斜面は、上の個体が隣へ滑り落ちる。最初の山は崩れない（山によっては最初から48°より急な所があるが、その斜面は最初の角度より 1cm 急になるまで崩れない）。2cm ほどの掘りではほとんど崩れない。深い穴は周りが崩れてすり鉢状になり、崖はならされる。クレーンの届く範囲が減ると、周りから崩れて補充される。
  - 滑った個体は元の場所のビットを立てたまま、行き先の柱の上の「崩れた層」に積まれる（ID は変わらず、つまむ・すくう・クレーンで取れる）。ちりモンも一緒に滑る。保存・書き出しに崩れた層を含み、途中で保存した崩れは読み込み後に続きから進む。1フレームに動かすのは最大 8,000匹。
  - 工場：空の設備（何も運んでいないコンベア・ホッパー・包装機・選別機）は待機電力（1/5）。処理間隔の端数を次へ持ち越し、高速包装機・ホッパーが表記どおりの速さに。改良の並びを 長いアーム → 高速クレーン → 大きなつかみ → 高速包装機 にして説明に効く条件を書いた。撤去ツールの説明に「クレーンは全額」。

- **0.10.1**：最初から急な斜面のある山（約2割）が、読み込みや近くの掘りで一気に崩れる不具合を修正。包装機を 0.12秒間隔（毎秒約165匹）、高速包装機を 0.08秒（約250匹）にして、改良（高速クレーン → 大きなつかみ → 高速包装機）を買うたびにライン1本の稼ぎが 約93 → 121 → 155 → 186円/秒 と上がるように。20匹未満しか入っていない包装機も待機電力に。

- **0.11.0 ラインに合わせた提案と、崩れの手応え**：
  - 「次の改良」は、いまの配置でのライン能力の見積もり（クレーン・ホッパー・選別機・包装機の上限を、各クレーンの出口からたどって計算）から「増える円/秒 ÷ 値段」が最も大きいものを勧める。ショップの改良に「いまのラインで 約+○円/秒」／「効果なし（包装機が頭打ち）」を表示。改良を買い終えても包装機が頭打ちなら「包装機を増やしてラインを分ける」と案内。
  - 崩れは時間に比例して進む（毎秒約40万匹、1フレーム最大12,000匹）。崩れた場所に砂煙と砂の流れる音。初めて近くで崩れたとき「深く掘るときは、穴を広げながら掘ろう」と一度だけ案内。目標 5/5 の文も崩れに合わせた。
  - 小さい画面（スマホ）でも建設画面の道具の説明を2行まで表示。照準の設備表示は待機中の消費電力を表示。床の個体は 4,000匹を超えても全部描く。山を処理し尽くしたあと、手・床・設備に残っている端数の場所を目標欄に案内。ポインターロックの連続要求で出ていたエラーを抑止。

今後の候補：大規模化（増設床・蓄電設備・複数ライン）、検品台・センサー、山ごとの記録の一覧。

数値（1パック＝20匹＝20円 など）は `src/config.js` にまとめた仮値です。

## 開発

```sh
npm install
npm run dev     # 開発サーバー
npm test        # 山モデル・保存則・搬送・電力・セーブ形式のテスト（P0〜P5 の合格条件）
npm run build   # dist/ に静的ビルド
npm run e2e     # ブラウザ通しテスト（要 Playwright: npm i -D playwright && npx playwright install chromium）
```

## 公開（GitHub Pages）

`main` に push すると `.github/workflows/deploy.yml` がテスト → ビルド → Pages へデプロイします。
初回のみ、リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にしてください。
